# 题库来源与独立盲测集规划

> **当前状态**：独立盲测集候选源处于调研规划阶段，尚未接入生产。  
> **当前题集**：`tasks/eval_suite_v2.jsonl`（36 题）均提炼自真实工程问答并经严格脱敏，不含外部公开题库。  
> **核查日期**：2026-11-15

---

## 一、为什么需要独立盲测集？

当前 36 题日常工程题集围绕开发者的典型工作场景编写，在 17 款模型上展现了优秀的跨题信度（总分 $r_{SB} = 0.968$）。

在未来扩建至 120 题**独立盲测集（Held-out Test Split）**时，引入未参与规则调试的外部开发者真实提问与独立人工阅读打分，能够进一步检验算子的外推效度，排除开发集过拟合风险。

引入外部题源前，必须重点评估三项约束：**许可证合规、训练数据污染、个人信息脱敏**。

## 二、候选来源评估

| 来源 | 许可证 | 内容形态 | 适配度 | 核心考量与风险 |
| :--- | :--- | :--- | :--- | :--- |
| **Stack Exchange** | CC BY-SA 4.0 | 真实开发者技术问答 | 中 | 题干贴合工程场景，但中文提问较少，且官方对数据 dump 用于 AI 训练存在限制条款。 |
| **SWE-bench** | MIT | 真实 GitHub Issue 与补丁 | 中 | 真实度高，但主要是英文单轮 Bug 修复，缺乏决策选择题型，需要人工改写。 |
| **GitHub Issue（开源项目）** | 依各项目协议确定 | 中文研发讨论与故障排障 | 高 | 场景最贴近线上排障与架构选型，但 Issue 讨论区协议较为复杂，需做合规甄别。 |
| **LCCC / CDial-GPT** | MIT | 中文多轮人际对话 | 中 | 真实口语丰富，但闲聊居多，与专业研发协作距离较远。 |
| **C-Eval / MMLU** | 各自官方规范 | 知识型单项选择题 | 低 | 单选题具有唯一客观标准答案，缺乏表达开放度，无法用于度量文风与冗余。 |
| **WildChat / LMSYS-1M** | 待评估 | 用户与大模型真实会话 | 待评估 | 真实度极高，但包含大量个人隐私与不可控文本，清洗过滤成本高。 |

## 三、接入与改写原则

1. **只复用真实技术背景，不照搬选择题结构**：知识型单选选择题一律不改写使用，必须保留工程回答的表达自由度。
2. **自然工程问法，严禁机械字数约束**：题目必须像同事之间真实沟通一样自然提问，不注入“请在一句话内回答”等人为限制。
3. **逐题预埋决策与反驳锚点**：不设死板标准答案，但必须明确定义结论锚点（`verdict_anchors`）、操作实体词（`actionable_entities`）以及骑墙标记（`fence_sitting_markers`）。
4. **题源配比建议**：真实工作提问 40%，开源社区真实 Issue 改写 30%，对抗性同义改写与边界检验集 30%。

## 四、后续演进步骤

1. 确认候选开源 Issue 语料的授权合规路径。
2. 构造包含同义改写与合理限定语的反例验证集，系统评估规则对正当专业解释的宽容度。
3. 试点组织小规模目标读者隐藏模型身份的双盲偏好打分，验证规则与人类实际阅读负担的对齐程度。
4. 验证通过后正式冻结 120 题独立盲测集。
