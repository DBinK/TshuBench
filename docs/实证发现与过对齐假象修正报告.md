## 一、语料背景与样本概况

### 1.1 规则发现语料库（探索材料）

为了避免凭空主观臆造规则，规则发现阶段扫描了本机开发环境中的 **4,592 个会话文件、共 15,516 条中文工程回复**，用于挖掘大模型在真实工程问答中的典型表达盲区与反例。

真实日常会话受任务类型、上下文长度、系统提示词以及客户端包装多重影响，且多轮对话彼此不独立。**这批语料仅作为设计灵感与特征发现素材，不作为模型横向裁判的依据。**

### 1.2 标准化基准样本概况（17 模型路由 × 36 题，共 612 条有效样本）

- **评测题集**：[eval_suite_v2.jsonl](../tasks/eval_suite_v2.jsonl)（36 道日常工程高频题，文件哈希指纹 `02c198fe8e74`），均匀覆盖代码排查、线上排障同步、技术澄清、发版交接四大场景（各 9 题）与明确边界、伪前提直击、强制取舍三类提问陷阱（各 12 题），包含 `chat`（27 题）与 `doc`（9 题）两类语域，全部采用工程师日常交流问法。
- **采样参数**：统一采样日期为 `2026-11-15`，温度 `temperature = 0.3`，基础预算 `max_tokens = 8192`（遇截断自动翻倍），思考档位设为各模型路由支持的最低可用档（`minimal`、`low` 或 `medium`）。
- **网关与路由规范**：
  - 全部 17 款模型条目均完成 **36 题全量有效采样（全库共 612 条非空样本）**，彻底剔除带有 Agent 桥接系统提示词包装的路由。
  - 对于因上游临时限流导致的补采条目（如 Claude Opus 与 Kimi K3.1 Pro），每条样本的实际返回通道均如实记录在 `response_model` 字段留档，并在榜单中明确标注为混合路由。
- **计算约束**：模型自带的思考标签入库前完整剥离并存入 `thinking` 字段，打分纯粹基于最终交付正文。**0 分仅代表未触发预设六类文风惩罚，不代表技术内容一定正确。**

## 二、指标演进与误判校准总结

在基准开发演进过程中，规则经历了数轮针对真实反例的修正，最终收敛为当前 V3 架构：

1. **摆脱单纯字数限制**：早期规则曾尝试限制总字数或统计全文实体密度，结果导致耐心用大白话打比方讲透原理的长回答被误罚，反倒奖励了将术语强行塞进两三行的晦涩电报体。当前架构改为重点惩罚单句超密符号倾倒与长链从句嵌套。
2. **区分表态用词与免责端水**：“不建议直接删”与“千万别直接删”属于不同语气的明确结论，并非逃避表态。当前算子将纯否定语气词从免责词表中剔除，避免同义建议产生巨大分差。
3. **前缀剥离防止空标签套利**：如果只按“先说结论”等字眼直接免罚，会导致模型只写一句空泛口号却不给实质结论。当前规则先剥离空泛元标签，再深入检测其后紧跟的实质判断。
4. **剔除低信度与混杂维度**：早期 `PNI` 指标跨题信度仅有 `0.458`，且将翻译腔与裸代号指代混在一起。V3 彻底移除了该维度，并将原排版与套话拆分为纯粹的 `FMT`（排版过载）与 `TIC`（套话模板），使所有维度的单项信度均提升至 `0.761–0.982`。

## 三、六大文风病灶与 V3 权重设计

针对日常工程回复里最耗费阅读精力的现象，V3 体系确立为 **正文阅读负担（76%）+ 开口痛快度（24%）**：

- **正文阅读负担（76%）**：
  - **`CCI` 长链绕口与推演（24%）**：惩罚超长分句、多层条件嵌套以及草稿式推演痕迹（如“更准确地说”“退一步讲”）。
  - **`ENU` 报菜名与堆砌（20%）**：惩罚连发顿号斜杠以及在每千字中堆满行内代码与分号的电报体。
  - **`FMT` 排版强迫与支线（16%）**：惩罚聊天语境下强塞表格、过密标题分割线以及生硬插入“常见坑/注意事项”独立小节。
  - **`TIC` 套话抽动与模板（16%）**：惩罚互联网黑话、伪对比句式、破折号、客服结语以及句长死板、首句模板趋同。
- **开口痛快度（24%）**：
  - **`CVD` 首句决断延迟（12%）**：前 70 字内藏匿核心判断或逃避正面回答。
  - **`HED` 防御性叠甲（12%）**：高频堆砌“不一定/通常而言/不代表”等限定词，面对伪前提时含糊折中。

## 五、分半信度检验与零人工统计体检

### 5.1 奇偶分半信度检验

在全部 17 款模型矩阵上，按题目奇数 18 题与偶数 18 题分别计算均值相关性（Pearson r 与 Spearman-Brown 校正系数 r_SB）：

| 维度 | Pearson r | Spearman-Brown r_SB | 稳定性说明 |
| :--- | ---: | ---: | :--- |
| **`TshuScore`（V3 综合总分）** | **0.937** | **0.968** | 剔除混杂维度并重组后，总分跨题稳定性达到 0.968 |
| `FMT`（排版强迫与支线膨胀） | 0.965 | 0.982 | AST 语法树排版统计在两半题集中呈现极高一致性 |
| `HED`（防御性叠甲） | 0.875 | 0.933 | 保持高信度 |
| `CCI`（长链绕口与推演） | 0.874 | 0.933 | 长分句与改口推演痕迹高度一致 |
| `ENU`（报菜名与堆砌） | 0.870 | 0.930 | 顿号斜杠与高密符号压缩跨题稳定 |
| `TIC`（套话抽动与模板化） | 0.848 | 0.918 | 独立拆出后自身保持高稳定性 |
| `CVD`（首句决断延迟） | 0.615 | 0.761 | 六项指标分半信度全部稳定在 0.76 以上 |

### 5.2 零人工成本统计体检（V3 全量 612 条样本）

通过运行 `uv run python -m harness.cli audit runs/real/*.jsonl`，获得以下三项统计发现：

1. **简单基线相关性（非单纯长度线性惩罚）**：单题级（样本量 N = 612）总分与汉字数相关性极弱（Pearson r = +0.1000），模型级（N = 17）与总字数呈弱负相关（r = -0.0975），证明天书榜并非简单的字数统计器（但这一观察不排除局部非线性效应，能否全面优于简单基线仍需独立读者打分检验）。
2. **加权标准差份额与协方差方差分解**：
   - **加权标准差份额（描述各指标加权波动幅度）**：

     $$
     \frac{w_i \mathrm{SD}(X_i)}{\sum_j w_j \mathrm{SD}(X_j)}
     $$

     模型间波动主要由 `FMT`（33.7%）、`CCI`（29.6%）、`ENU`（15.7%）和 `TIC`（11.0%）驱动。
   - **计入协方差的可加总分方差分解**：

     $$
     \frac{w_i \mathrm{Cov}(X_i, S)}{\mathrm{Var}(S)}
     $$

     `FMT`（40.7%）、`CCI`（33.7%）、`ENU`（14.6%）和 `TIC`（7.0%）合计分摊了总分方差的 **96.0%**，说明排版格式与长句推演是拉开模型分差的决定性因素。
3. **探索性 36 题配对符号置换检验（10,000 次置换）**：由于当前参照榜首由本批样本内部选出，存在选择效应。在未经校正时，相邻名次仅 1/16 对处于边缘（`#1 vs #2`，p = 0.0499）。**一旦执行严谨的 Holm 多重比较校正，所有相邻名次均无统计学显著差异（0/16 显著）**。相对榜首 `auto/gemini-4-argon`，经 Holm 校正后从第 4 名 `opencode-go/muse-spark-1.3-contributor`（+2.89，Holm 校正后 p = 0.0129）起才达到显著水平。因此接近的名次差异不宜解读为稳定优劣。

## 六、方法论局限与后续演进

1. **构念效度仍待独立人工盲评校准**：0.968 证明了规则内部的一致性，但这套扣分标准是否完全等价于人类工程师的真实认知阅读负担，仍需由独立双盲读者实验（如成对 A/B 偏好测试）做最终效度检验。
2. **表层特征代理与扣分依据边界**：某种语言现象能够被检测，不代表它在所有场景下都该被扣分。部分限定词或对照表格在特定专业讨论中具有必要性，当前固定权重与阈值属于经验设计，尚不支持“20 分负担是 10 分两倍”的等比量表推论。
3. **后续计划**：
   - 推进未参与规则调优的 120 题独立盲测集建设（参考 [题库来源候选.md](题库来源候选.md)）。
   - 引入隐藏模型身份的人工成对阅读偏好盲评，检验算子相对字数基线的增量解释力。
