# TshuBench · 天书榜

> **量化大模型中文工程回答里的“不说人话”与阅读负担**  
> 拒绝 LLM-as-a-Judge 裁判偏见，基于纯规则 AST 语法树与词法统计，100% 确定性复现。

---

## 什么是天书榜？

在日常研发协作中，你是否经常觉得 AI 给的答案**读起来很累**？

- **开场打太极**：问第一步先干嘛，它先洋洋洒洒铺垫三段背景复述，就是不给结论。
- **通篇报菜名**：动辄连发十几个顿号与斜杠，或者把几十个行内代码块像电报一样硬塞进几行字里。
- **长句绕口推演**：正文里满是“换句话说”“更准确地说”“退一步讲”，拿思考草稿当最终回答，还嵌套着超长条件句。
- **即时聊天硬塞表格墙**：问个简单的排障命令，强行输出七八行 Markdown 大表格和层层多级标题。
- **逢人便叠甲**：明明是常识，非要塞满“不一定”“通常而言”“不代表”等防御性免责词。

**TshuBench（天书榜）就是为了度量这些文风病灶而生的启发式基准。** 它从开发者真实工程提问中提炼了 36 道高频题（涵盖排障、代码审查、技术澄清与发版交付），不用任何大模型当裁判，完全通过确定性算子直接计算文本的阅读阻力。

**分数越低越讲人话，分数越高越像天书。**

## 核心设计原则

1. **零裁判模型（Zero LLM-as-a-Judge）**  
   不用任何 LLM 给回复打分。学术界已证实 LLM 裁判普遍存在严重的“喜欢长回答”与“排版偏见”。天书榜全部基于 `markdown-it-py` 语法树解析与确定性词法正则，同一份回复计算一万次也是同一个分数。
2. **惩罚电报体压缩与结构膨胀，不搞单纯字数歧视**  
   用大白话耐心讲透前因后果的长回答不会受罚。真正扣分的是单位字数内的高密符号压缩、长链从句嵌套、聊天语境强塞表格墙与防御性叠甲。
3. **只评表达风格，不判技术对错**  
   0 分仅代表未触发六类预设文风惩罚，不代表技术结论一定正确。
4. **全链路真实可溯源**  
   公开每条样本的思考档位、温度参数、截断重试记录与实际路由通路，杜绝不可复现的黑盒排行。

## 六大核心指标速查（V3 体系）

总分由**正文阅读负担（76%）**与**开口痛快度（24%）**两大模块构成，按实际体感冲击与区分度排序：

| 模块 | 代号 | 指标名称 | 权重 | 针对的核心问题 |
| :--- | :--- | :--- | ---: | :--- |
| **正文** | **CCI** | 长链绕口与推演 | 24% | 超长纯汉字分句（>28 字）、多层条件嵌套、分号长链、高频“的”字以及正文外显的草稿推演痕迹（如“换句话说”“退一步讲”） |
| **正文** | **FMT** | 排版强迫与支线 | 16% | 在即时问答中强塞 Markdown 表格墙、过密标题分割线、超额代码块，或强行插入独立“常见坑/注意事项”摊大饼 |
| **正文** | **ENU** | 报菜名与堆砌 | 20% | 单句连续顿号斜杠连发，或在每千字里密密麻麻塞满行内代码与分号的电报式压缩 |
| **正文** | **TIC** | 套话抽动与模板 | 16% | 互联网黑话、伪对比句式、滥用破折号插入语、“随时告诉我”客服套话，以及句长死板均一与首句模板趋同 |
| **开口** | **CVD** | 首句决断延迟 | 12% | 剥离“先说结论”等空泛标签后，前 70 字内藏匿核心判断或逃避正面表态 |
| **开口** | **HED** | 防御性叠甲 | 12% | 高密度堆砌“不一定/取决于/通常而言/不代表”等免责限定词，面对伪前提时和稀泥 |

## 30 秒快速上手

本项目使用 [uv](https://github.com/astral-sh/uv) 管理依赖与运行环境。

### 1. 安装与离线演示
```bash
# 同步环境
uv sync

# 运行自动化单测
uv run pytest -q

# 生成并评测一套离线 Demo 样本
uv run python -m harness.cli run --demo --out-prefix runs/demo
uv run python -m harness.cli score runs/demo_tidy.jsonl runs/demo_slop.jsonl
```

### 2. 评测真实模型
只需提供任何兼容 OpenAI 协议的接口地址与 Key：

```bash
# 采样并自动打分单个模型
export OPENAI_API_KEY="sk-xxx"
uv run python -m harness.cli suite \
  -m deepseek-chat \
  --base-url https://api.deepseek.com/v1 \
  --out-dir runs/real

# 也可以离线批量对现有样本打分并刷新报告
uv run python -m harness.cli score runs/real/*.jsonl --out reports --html web/index.html
```

### 3. 一键统计体检
查看当前模型矩阵的基线对照、方差分摊与配对置换检验：

```bash
uv run python -m harness.cli audit runs/real/*.jsonl
```

## 评测边界与方法论声明

- **启发式指数定位**：天书榜是基于工程直觉与语言学动机设计的文风观察指数。目前尚未完成大规模独立读者双盲实验校准，总分体现的是在预设规则下的风格偏向，不支持“20 分负担是 10 分两倍”的等比量表解释。
- **信度与统计检验**：当前总分奇偶分半信度达到 `0.968`，表明规则在 36 道题上具有高度的内部一致性。在配对符号置换检验中，经 Holm 多重比较校正后，相邻名次之间无统计学显著差异，接近的名次差异不宜过度解读。
- **与字数并非简单线性绑定**：实测显示总分与回复字数呈极弱相关（单题级汉字数 $r = +0.1000$），并非单纯按长短扣分。
- **单轮静态采样约束**：榜单反映特定日期（2026-11-15）与固定参数（`temperature=0.3`、最低思考档位）下的单轮静态表现，后训练过对齐归因仍属待深入验证的机制假设。
